# 组合设计检查示例

用于修改组合检查要求后的内容审查，不是可运行模块。检查方法见[主提示词](prompt.md#组合设计)，验收要求见[检查标准](../VALIDATION.md)。由智能体按具体材料作出判断并记录依据，不能用关键词匹配代替审查。

## 创作、检查和保存共同交付作品

任务是向剪辑人员交付检查通过、可读取的分镜文件。外部提供原文、创作要求和保存位置，已有资产资料仅在需要沿用时提供。创作成员产出分镜草稿，检查成员对照原文、要求和草稿版本检查；不通过时退回创作修改，缺少必要资料时停止并说明。通过后保存同一版本的分镜，回读成功才交付分镜及文件位置。保存失败保留已检查的分镜并报告未完成，不报告已保存。

合格条件是分镜覆盖本次要求的原文、符合创作要求，检查结论对应交付版本，保存文件能够回读。检查报告供内部判断或按需要附带，不能代替分镜。

预期判断：设计合理。三个成员分别负责产出、把关和保存，服务同一份交付。没有真实运行证据时，只能确认此示例的设计关系，检查和回读效果仍待验证。

## 独立操作共用一个结果名称

外部传入操作名称和对应材料，可任选提取原文、设计分镜或检查项目。三个成员分别返回原文、分镜或项目问题报告，彼此不交接；组合把任一结果原样返回为“操作结果”。每个输出都已连接到组合输出，但没有说明这些独立操作共同完成什么交付。

预期判断：现有依据不足以认定为合理组合。输出有来源不代表存在共同任务；应指出职责和协作依据的缺口。项目可以提供这些独立入口，不能据此要求删除功能，也不能只改结果名称就宣布问题解决。

## 同一任务有正文、附件和可选步骤

任务是向活动负责人交付可执行的活动方案。外部提供活动目标、日期、人数和预算上限；提供餐饮时另需饮食要求，可附已有的合格预算明细。策划成员生成正文；预算成员在没有适用预算明细时制作附件，有适用明细时使用已有材料；餐饮成员仅在提供餐饮时补齐安排。检查成员核对正文和附件的人数、日期、金额是否一致，预算是否超限，以及适用的餐饮要求是否落实；不通过退回对应成员，缺少必要材料时停止。通过后交付方案正文和预算附件，餐饮安排按适用条件纳入正文。

预期判断：设计合理。多份成果、条件分支和已有材料接入均服务同一份可执行方案，不要求每次执行所有成员。没有实际执行证据时，不能据此认定程序已支持这些条件或实际方案合格。
