# 检查标准

验收需要原始请求、实际读取材料、检查报告；复查还需上次报告和修复内容。

- 目标和合格交付有项目依据，不自行增加业务目标或要求重构。
- 覆盖各项任务入口、相关模块和完整交付路径，包括失败、退回、停止及恢复；未覆盖部分列明原因，不把抽查说成全查。
- 判断材料能否支持下一步处理、结果能否满足目标，不只核对接口名称或文件齐全。
- 已确认问题有具体位置、证据、影响和可执行建议；推断风险、缺少验证和需用户决定的事项分开列出。
- 实际运行结论对应具体输入、预期、结果和证据；静态阅读或受控调用不冒充实际业务验收。
- 两个配套模块及结构检查的状态、范围和报告是否适用于当前版本均明确；缺报告不写通过，同一问题不重复计数。
- 复查逐项核对旧问题、关联流程及新问题。报告只存入指定任务目录，返回内容与实际保存一致，未修改被检查项目或发起外部操作。

内容判断仍须由智能体实际执行，结构检查通过不能代替本模块验收。
