# 检查标准

验收需要原始请求、实际读取材料、检查报告；复查还需上次报告和修复内容。

- 目标和合格交付有项目依据，不自行增加业务目标或要求重构。
- 检查对象与用户指定范围一致；其他项目的参考材料不作为跨项目操作授权。
- 覆盖各项任务入口、相关模块和完整交付路径，包括失败、退回、停止及恢复；未覆盖部分列明原因，不把抽查说成全查。
- 判断材料能否支持下一步处理、结果能否满足目标，不只核对接口名称或文件齐全。
- 组合设计结论有明确的交付对象、成果、外部输入、完成标准及成员贡献依据；内部材料与对外成果区分清楚，检查报告未被当作所需业务成果。
- 同一任务的多份成果、条件分支和已有材料接入未被误判；仅将独立操作归类、缺少共同交付的问题未被漏报。项目多个任务入口按声明用途分别检查。
- 组合正常交付及适用的失败、退回路径有实现或执行依据，缺失部分列为待验证；结构通过未替代设计结论，证据不足未被认定为设计完成。
- 已确认问题有具体位置、证据、影响和可执行建议；推断风险、缺少验证和需用户决定的事项分开列出。
- 实际运行结论对应具体输入、预期、结果和证据；静态阅读或受控调用不冒充实际业务验收。
- 有交互界面时，结论有接近实际规模的完整操作证据，覆盖相关导航、响应和保存结果；页面能打开或自动测试通过不代替使用验收。
- 两个配套模块及结构检查的状态、范围和报告是否适用于当前版本均明确；缺报告不写通过，同一问题不重复计数。
- 复查逐项核对旧问题、关联流程及新问题。报告只存入指定任务目录，返回内容与实际保存一致，未修改被检查项目或发起外部操作。

内容判断仍须由智能体实际执行，结构检查通过不能代替本模块验收。

修改组合检查要求后，使用[组合设计检查示例](implementation/组合设计检查示例.md)逐例执行内容审查。三类样例的结论和证据须分别记录；程序测试只能证明相应结构与状态行为，样例审查通过不能证明智能体在其他任务上判断可靠。
