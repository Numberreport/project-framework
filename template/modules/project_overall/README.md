# 项目整体检查

## 职责

检查项目能否从目标、输入走到合格交付，找出模块分工、流程衔接和实际效果中的缺口。只报告问题，不修改项目。由当前智能体执行[主提示词](implementation/prompt.md)。

## 输入

接收 request：项目位置、该项目 workspace/ 下的任务目录，以及可获得的项目目标、典型任务和验收证据。复查时提供上次报告及修复内容。可附项目口径检查、可读性检查和结构检查的当前报告；没有时说明缺项，不视为通过。

```interfaces
[{ "name": "request", "description": "项目位置、任务目录、可获得的目标与典型任务及验收证据、配套检查报告；复查时的上次报告和修复内容" }]
```

## 输出

交付 report：整体检查报告正文和保存路径；保存失败时返回正文及原因。报告包含已确认问题、风险、待确认事项、覆盖范围和配套检查状态。

```interfaces
[{ "name": "report", "description": "整体检查报告正文、保存路径或保存失败原因" }]
```

## 处理流程

在对话中要求“检查项目整体”即可调用，由当前智能体填写输入。按[主提示词](implementation/prompt.md)检查，以[检查标准](VALIDATION.md)验收。

本模块与[项目口径检查](../project_consistency/README.md)、[可读性检查](../prompt_readability/README.md)配套使用：前两者分别查做法一致和文字易懂，本模块查目标、分工、完整流程及结果。要求“三项配套检查”时，由当前智能体分别执行两个已有模块，再把当前报告交给本模块；单独调用整体检查时不自动执行其他模块，不用整体结论替代其报告。

本模块在画布独立显示，不接入项目业务连线。程序调度时对本模块目录调用 runProject，由调用方提供具备读取项目和保存报告能力的 executeAI。

## 没完成时

缺项目位置或无法确定目标时说明缺项。材料不足、无法读取或无法验证实际效果时，交付受限报告，不声称项目整体通过。修复由当前智能体负责，再调用本模块复查；业务取舍没有明确依据时请用户决定。
