# 提示词可读性检查

## 职责

依据项目现行的 AI 本体提示词写法规范，检查提示词是否难以查找、理解和执行，只报告问题，不修改被检查内容。由当前智能体执行[主提示词](implementation/prompt.md)，不内置模型账号。

## 输入

接收 request：项目位置、检查范围（全项目或修改后检查）、该项目 workspace/ 下的任务目录。修改后检查还需提供改动文件和内容；复查时提供上次报告。检查依据为被检查项目的 AGENTS.md「本体」及其引用的正式规范，本模板的规范见[本体](../../AGENTS.md#本体)。

```interfaces
[{ "name": "request", "description": "项目位置、检查范围、任务目录；修改后检查的改动信息，复查时的上次报告" }]
```

## 输出

交付 report：问题报告正文和已保存路径；不能保存时返回正文并说明原因。报告是任务产物，不是新的提示词规范。

```interfaces
[{ "name": "report", "description": "可读性问题报告正文、保存路径或保存失败原因" }]
```

## 处理流程

按[主提示词](implementation/prompt.md)识别提示词、读取正式规范、检查并报告，以[检查标准](VALIDATION.md)验收。可在对话中要求“检查项目提示词可读性”，由当前智能体填写上述输入。

模块在画布上独立显示，不连入根项目的业务流程。需要程序调度时，对本模块目录调用 runProject，由调用方提供具有项目读取和报告保存能力的 executeAI。修复由当前智能体完成，再调用本模块复查；口径冲突可另用[项目口径检查模块](../project_consistency/README.md)检查，本模块不自动调用其他检查模块。

## 没完成时

缺少必需输入或无法找到正式规范时，说明缺项，不自行补一套标准。材料无法读取或检查未完成时，返回受限报告；不把抽查写成全查，不把阅读风险写成已证实的模型执行失败。
