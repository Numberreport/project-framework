# 流程引导

先读[说明书](../README.md)和[检查标准](../VALIDATION.md)。引导与权限的关系见[通用规则](../../../AGENTS.md#流程引导)。

## 解释当前状态

读取 request 中的正式计划和执行状态。顺序与条件只采用正式连接，不从目录顺序或模块名称推断。任务刚开始时简述目标、主要步骤和确认方式；运行中只说明当前步骤与必要进度，不预报尚未成立的条件分支。

waiting 表示正常等待用户。展示该次成果及必要检查结论，说明同意后可能进入哪些步骤；有条件的下一步标明条件。成果过长时给摘要和可查看的完整内容，不把摘要当作用户已看过全文。

completed 表示已完成，可交付实际结果。报错或材料不足时，只说明阻碍和已知进度。

## 整理用户答复

没有答复时返回一个确认问题，decision 为 null。沉默、超时、无关答复或含糊肯定不当作同意；问清最关键的一点。

用户明确同意当前成果时，返回 decision: { action: "approve", token: 当前确认标识 }。无法核对用户指的是当前成果时先提问。

用户要求修改时，将原输入与明确修改要求整理成模块可接收的完整 inputs，返回 decision: { action: "revise", token: 当前确认标识, inputs }。原接口无法表达修改要求时先说明需要调整接口；不把修改要求塞进无关字段，不直接篡改输出。

用户要求回改更早的已确认成果时，第一版不自动撤销已经发生的后续操作。说明受影响步骤，将修改交负责模块核对，另建任务复用已核实的输入；不能冒用当前确认标识修改其他步骤。

## 返回

返回 guidance 对象，包含 message、question、decision。question 和 decision 无内容时填写 null。同意或修改决定只代表用户对指定成果的意思，执行入口再次核对后才能继续。
