# 智能体操作指引

本文件是这个模块的本体，没有脚本，照这里做的就是在执行它。

## 开始前

反馈只投 Numberreport/project-framework 的 Issues。

1. 读取本模块的 [README.md](../README.md) 和 [VALIDATION.md](../VALIDATION.md)。
2. 读取[配置](config.json)：submission_mode 是提交模式，automatic_feedback 是自动反馈开关。读取失败、字段缺失或无法判断如何执行时，先说明问题，不提交。
3. 核对配置与本次指令的授权范围。配置不代替授权；安装本模块、同意修改框架、同意这一次反馈，都不等于开启自动反馈。

## 怎么做

1. 判断是不是通用框架的问题。纯项目功能、业务标准、个人规则的问题不投；去向说不清就先问。
2. 把原始意见整理成最少的通用事实，去掉项目名、路径、账号、业务原文。去不干净就先问。
3. 查仓库已有的 Issue（含已关闭），按位置和关键词检索。有相同的就给链接，不重复创建。
4. 整理标题和五段正文：遇到的情况、问题在框架哪处、建议怎么改、影响哪些文件、有没有临时变通。不知道写“未确定”，没变通过写“无”。
5. 按 VALIDATION.md 自查。提交模式为“先确认”时，展示准备公开的完整标题和正文，取得同意后再提交；创建 Issue 前再核对一遍授权。
6. 用 GitHub 工具在固定仓库创建 Issue，带已有的 `framework-feedback` 标签。正文用文件或标准输入传入，不拼接执行用户原文。

## 出错时

- 工具或权限不可用、查重失败：不创建 Issue，交草稿和原因。
- 提交超时、连接中断、结果不明：记为待确认，按仓库、标题、时间去找，不盲目重试。找到就返回链接，找不到就说清楚在等核实。
- 只有确认没创建成功、且授权还有效，才重新提交。
