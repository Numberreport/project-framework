# 智能体操作指引

先读上一级 INPUT.md、OUTPUT.md、PROCESS.md、VALIDATION.md 和 settings/ 中实际生效的设置。本文件是执行入口，无独立脚本。通过当前智能体可用的 GitHub 工具完成查询和提交，优先使用已连接工具；必要时可用本机已有、已登录的 GitHub CLI。不得自行安装工具、登录新账号或读取输出凭据。

## 范围与隐私

框架本身的规则、模块模板、检查、通用方法和使用入口属于本模块范围。纯项目功能、业务标准或个人规则问题不投给框架仓库；说明原因，去向不清时只问最关键的问题。

将原始意见提炼为最少的通用事实，移除项目名称、绝对路径、账号、业务原文等隐私。只写框架内的相对位置和通用示例，不上传原文件、完整对话、截图或日志。必要事实被移除后无法说明问题，或无法判断能否公开，先问；自动模式不跳过这一步。用户直接使用 GitHub 表单时，也提醒其按表单隐私要求填写。

## 查重与草稿

查询 Numberreport/project-framework 的 Issues，包含已关闭问题，用发生位置和问题关键词检索，并读取相关内容再判断，不只看标题相似。相同问题已有反馈时交付已有链接及状态；不自动新建、评论、重开或关闭。相似但不能确定是否同一问题时先问，不猜重复或独立。

按现有反馈表单准备一个标题及五段正文：
- 遇到的情况。
- 问题在框架哪处。
- 建议怎么改。
- 影响哪些文件。
- 是否已临时变通。

框架位置可以是模板文件或方法章节，影响文件不明写未确定。已做的操作才写已做；没有变通写无。不得把拟实施方案写成已经完成。尚未取得授权时，准备和只读查重可以进行。

## 授权与提交

先确认模式下，展示准备公开的完整标题和正文，请使用者同意提交。若用户已明确要求提交这份确定内容，则不重复问。拒绝就不提交，不把拒绝记录成偏好。

自动模式下，核对生效设置中的开启依据、具体范围和固定目标是否覆盖本次问题。只有明确覆盖时免逐条确认；仅有候选、范围含糊、授权冲突或更严格规则要求逐次确认时，仍先问。用户提出或智能体发现的问题都按同一范围判断，不把本次采用模块视为开启自动模式。

提交前按 VALIDATION.md 审阅并再次核对当前授权，避免等待期间授权已撤销。使用 GitHub 工具在固定仓库创建 Issue，标题概括问题，正文使用上述五段，使用已有 framework-feedback 标签；不擅自创建标签。CLI 使用正文文件或标准输入保留真实换行，不拼接执行用户原文。

## 结果、失败与恢复

有工具返回确认的 Issue 链接才报已提交。若查询确认已有问题，报已有反馈。GitHub 工具或权限不可用、查重失败时不创建 Issue，交付安全草稿和未提交原因，用户可通过 README 的表单转交；查重未完成须明确说明。

提交超时、连接中断或返回不明，状态记待确认；用目标仓库、标题、当前账号及时间线索查找并读取结果。找到确认记录则返回链接，不再次创建；仍不能确定就保留安全摘要、说明待核实并等待，不盲目重试。只有确认未创建后，才在原授权仍有效时重新尝试。

结果仅交付到当前对话。用户要求留存时才按本模块保存要求保存安全草稿、授权依据和确认链接，不保留凭据或原始私有材料。此模块不会自动修复问题，也不会处理维护者后续关闭流程。
