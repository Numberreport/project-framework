# 配置检验标准

检验模块的输入是目标模块配置和本标准，输出通过或不通过及具体原因；缺少依据或工具时为未完成。可由程序核对结构、由智能体审阅语义，不增加特殊模块类型。

- 每个位置有独立配套文件，必需内容完整，模板版本受支持，标识唯一；pending 模块不得启动。
- 输入、输出、流程可实际执行，包含命名信息项、启动指令、完成要求及必要失败处理；程序、AI 指引均有实际入口。
- 组合成员来自直接目录，连接只接本层成员及自身；输入输出匹配，转换显式，反馈有实际可执行的停止条件。
- 默认设置和偏好分开，优先级及授权清楚，不用偏好覆盖必须条件；不含凭据。
- 实现、工具、知识及本地链接可访问，适用时有时效、来源、保存与恢复要求。
- 维护验收脚本若配置则在本模块内；全景与来源一致。

check.mjs 核对文件、标识、版本、路径和连接等结构；其余由审阅或项目专用检验确认。业务检验未接入也不能跳过配置检查。配置不通过暂停受影响模块，不阻塞独立模块。
