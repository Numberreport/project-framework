# 运行与维护

## 启动与设置

输入满足要求并收到运行指令才处理。对话与页面按钮调用同一模块；明确位置、输入和本次要求，歧义先问，已知信息不重复问。程序也要读取所需输入文件。必需输入不足先补齐，可选缺失不阻塞。

每次读输入、输出、流程及最终生效设置，知识按需读。设置优先级是本次明确要求、适用用户偏好、组合显式传入值、模块默认值；组合不自动下传全部设置。组合与成员偏好冲突先问。优先级仅适用于可调整选项，不能覆盖输入和流程中的必须条件。记录最终生效值，改设置只影响新分身。

运行前检查已有结果：输入、处理要求及影响结果的设置一致，仍有效且满足本次要求就复用；否则重做，用户要求重跑则重跑。输入按需核对有效期、时间、范围、单位与可接受限制；过期可保留，不能作为当前有效输入。来源、限制随输出保留，同源引用不算独立证据。

## 分身与交接

每次调用创建独立分身，包括单个任务；共享模块定义，各自记录输入、版本、进度、结果、错误及实际设置。组合的内部任务也隔离。新任务默认最新输入并固定版本，恢复沿原输入，须能找回固定副本或历史引用。交接匹配任务标识及输入版本，旧结果迟到标明来源，不混作新版。

结束分身自动消失，记录由所属模块统一管理；等待、可恢复和状态待确认的任务继续跟踪。框架不设统一并发上限，实际受资源与服务约束；争用资源时只排队相关步骤。共享数据交给统一写入口。

批量每项独立，汇报全部、部分或全部失败，未知另列。只重试确认失败项，成功项不重复执行。下游按所需逐项交接或等整批；组合结束前处理剩余任务，无法确认取消仍保留编号跟踪。

长期运行按流程指定频率或触发条件、停止条件及失败后是否继续，可直到用户停止。每次处理独立分身；停止不再新增，已有分身按取消和恢复规则处理。

## 检验与修正

检验按需连接，输入输出、标准和所需原始依据，输出通过或不通过及全部已发现问题，逐条说明违反的标准及位置，不增加要求。工具失败、缺依据、超时属于未完成，不伪装内容不通过。不接直接交付但不宣称检验合格；检验模块可再接检验，不强制无限复核。

采用本任务标准版本，检验完整输出。不通过时将原要求、上一轮结果和历次意见交回原模块，优先修问题但重验完整结果。默认最多完成 5 次修正，首次生成和检验调用失败不计入。用完暂停保存；按原要求继续默认追加 5 次，累计轮次保留。输入、目标、标准改变创建新任务。

整个循环归同一任务，每次生成和检验各有分身；各轮结果、意见、版本和次数统一关联。标准由业务模块 VALIDATION.md 规定，检验如何执行由检验模块流程规定；可靠性验证与每次运行是否接检验分开。

## 授权、失败与恢复

外部工具在 README 声明，由运行入口提供连接，缺失暂停相关步骤。账号密钥不进入模板、知识、记录。读取、修改、发布等分别授权，组合不能扩大权限；已授权范围不重复问。

默认不允许外部工具付费，需要时问；明确设置允许后在任务与次数范围内不重复问。智能体自身生成、检验、修正不受外部付费开关限制。5 次修正不自动授予付费权限。

输入不合格不正式处理。临时故障默认重试一次，可能重复付费或产生重复操作不自动重试。缺材料、授权或偏好冲突保存进度等用户，不占执行名额，不阻塞独立步骤。成员失败暂停依赖项。超时状态未知先查原任务编号，不重新提交；取消须尝试核实，无法确认继续跟踪。恢复前核对结果及输入有效性，不重复执行，失效先处理，不能悄悄切换新输入。

执行完成、检验合格、正式保存分别判断。未通过已接业务检验的产物不能进入正常下游，可走修正反馈。只提交成功或文件存在不算整体交付完成。

## 保存与清理

runs/ 按任务标识保存可恢复记录，组合关联内部记录，不必复制共享材料；默认永久。可设保存天数（结束起算）或只留最后一次（按结束时间，最近失败时同时保留最近成功）。项目提供默认，各模块可覆盖；运行中、等待恢复、未知和依赖恢复所需记录先保护。分身不各自另留一份永久历史。

明确要求保存或本次指定正式交付时，进入 outputs/，不强制再确认。正式成果默认永久，同名另存版本，明确替换才覆盖；组合可引用成员成果。删除覆盖按授权，清理历史不删除用户原始资料、正式成果和仍被引用文件。

清理由独立模块完成：输入保存设置、记录、引用和状态；列候选，排除保护项，核对引用，执行前重查，报告删除、保留、失败。不确定先留。启用自动清理前须按此流程实现并验证；模板未附自动删除工具。

## 更新与启动复查

升级比较旧模板、新模板、当前文件，保留当前位置配置偏好；冲突或不兼容先问。留可恢复版本，检查后更新版本记录，失败回滚；找不到旧模板不能猜合并。

更新暂停新任务，已有分身优先完成，必须中断则保存进度，随后统一重启。先查原外部编号恢复，不重复提交；流程变化先核对旧任务兼容性，不兼容保留现场询问。普通设置改动不要求当前分身重启。

已有项目切换前明确由谁授权和操作、哪些检查通过才切换，以及何种异常须停止。停妥旧入口与定时任务，确认在途外部操作状态，再启用新流程，避免新旧两边重复执行。权限、兼容、数据或任务状态无法确认时，停止受影响部分的切换，保留现场。

失败恢复按顺序进行：暂停新流程，核实在途任务及已产生的结果，恢复兼容的代码与配置，检查数据和引用，再恢复原任务及调度。回退代码时保留新增数据、成果和任务恢复线索；若旧代码无法读取新数据或状态，先停下询问，不直接覆盖数据或重新提交外部操作。

先检查配置与连接，再复查历史成果；配置失败只暂停受影响模块。输入、知识、影响内容的设置变化使依赖旧产物待更新，不自动重跑；保存期限变化不影响内容有效性。

每次启动，仅对已接业务检验且有保留成功产物的模块，按结束时间选最近成功产物，用当前标准复查；没有就不查。不通过保留并标记需重做，暂停依赖项，不自动修正生成。复查只追加检验及状态，不改原业务时间顺序，不挤掉旧成果；旧成果通过不能证明新流程可靠。
