# 模块模板与中文对照

本页规定配套工具使用的具体格式，不是模块化的唯一定义。模板格式版本为 2.0.0，标识 project-framework。当前工具将项目根目录按组合结构读取；这是实现约定，不要求所有项目在概念上都是单个模块。普通模块、组合和项目根目录使用以下文件：

| 英文名称 | 中文与用途 |
| --- | --- |
| module.json | 模块信息：id 稳定标识、name 显示名称、template 模板标识及版本、status 配置状态 |
| README.md | 职责、使用说明、启动方式、文件入口和外部工具；职责写在“职责”二级标题下，先用一段话说明负责什么 |
| INPUT.md | 输入来源、要求、必需与可选项，按需写有效期及匹配条件 |
| OUTPUT.md | 命名输出、格式、交付保存位置，按需写来源及限制 |
| PROCESS.md | 处理步骤、启动、失败、人工确认，按需写长期运行与停止条件 |
| VALIDATION.md | 业务输出标准 |
| settings/DEFAULTS.md | 默认设置 |
| settings/PREFERENCES.md | 当前位置用户偏好；候选和生效分开 |
| implementation/ | 程序或 AI 执行指引，由流程引用 |
| knowledge/ | 可选知识与资料引用 |
| modules/ | 仅组合需要，直接目录为成员 |
| connections.json | 仅组合需要，唯一连接登记 |
| runs/ | 执行时创建的运行记录，按任务标识区分 |
| outputs/ | 执行时按需创建的正式成果 |

配置标准位于方法目录的 CONFIG_VALIDATION.md；模块按自身位置引用，不复制正文。无需为凑齐目录建立空知识库、运行记录或成品目录。不强制模块自带测试。

输入、输出、流程只填实际需要的条件。不为时效、来源、复用等各建一份文件或规则层级。

当前资料按需放在各模块 knowledge/，模块注明引用和用途；已有资料引用原处，不重复复制。参考资料供查阅，必须遵守的处理要求仍在流程中维护。

## 模块信息

id 使用字母、数字、下划线、短横线，以字母或数字开头，项目内唯一；显示名称可改。新模块或改到一半时 status 为 pending，编辑过程中内容可暂缺；必需内容补齐、结构齐备并经配置检查及人工确认后，才改为 ready。检查不会自动替你改状态。模板的就绪示例可运行，复制到新位置须重新配置。

verify 可选，写本模块内的 implementation/verify.mjs 等相对路径；只允许 Node .mjs 脚本，不含参数、绝对路径、.. 或跨模块引用。它是维护验收，不是业务检验连接，普通模块和组合都不强制配置。外部工具的业务检验执行方法由检验模块规定。

以下两个可选字段用于中端定位执行方式和实现，工具按下列约定检查：

- processor：字符串，只取 program、ai、mixed，分别表示程序、AI、两者配合。它只描述执行方式，不授予执行权限。
- implementation：字符串，指向本模块 implementation/ 内的一个入口文件，可为程序或 AI 执行指引。使用相对路径和 / 分隔符，不含参数、绝对路径、.. 或跨模块引用；解析后的实际路径也须在本模块 implementation/ 内。如何调用、需要哪些设置、怎样使用共享实现，仍由 PROCESS.md 和入口文件说明，不另列整套实现文件清单。多个入口可由一份执行指引说明选择方式，不为登记路径强加统一调用器。

implementation 不替代 verify；业务标准仍在 VALIDATION.md，业务检验执行仍由检验模块流程和连接决定，不新增 entry 或 validation 字段。路径存在不代表可以执行、检验通过或已获授权；中端只提供只读定位，不据此自动运行。

旧模块可以不填写这两个字段或 README.md 的“职责”段，仍按原配置使用。缺项显示“未填写”，不按名称、文件扩展名或业务内容猜测，也不自动改写。职责摘要读取“职责”段的首段，详情显示完整段落；不在 module.json 或布局文件重复保存。职责缺项由审阅指出，不因新增约定直接阻止旧模块运行。

升级前须核实已有模块和连接中 processor、implementation、kind 同名字段的真实用途，包括旧连接允许保存的自定义 kind。存在用途冲突或无法确认时，不自动按新含义解释、不改写、不启用新检查；保留原文件与旧工具，提出迁移方案，经用户确认后再迁移并采用新契约。采用新契约后，填写的字段才按本页约定检查。其他自定义 entry、validation 配置也须先核实再迁移，不自动套用本契约。

## 多个任务入口

各任务对应根 modules/ 下的直接成员，可以是普通模块，也可以是组合模块。单个普通模块能完成的任务，不必另套组合。根 INPUT.md 为各任务定义命名输入及适用条件，OUTPUT.md 定义对应输出；根 PROCESS.md 写明根据哪项指令选择哪个任务，以及输入不足或指令不明时如何处理。只检查所选任务及其依赖需要的输入，其他任务缺输入不阻塞。connections.json 用这些端口连接对应成员，并用 when 注明任务选择条件。组合内部的入口模块仍由该组合自己的连接定义。

例如，整理与检查两项任务可分别使用 organize_text 和 check_text 输入，并连接到各自成员模块；本例启动指令选择其中一项，不默认执行全部成员。README.md 列出各任务的实际启动方式。程序或智能体按 PROCESS.md 选择并执行，when 只是条件说明，检查工具不会自动调度。当前文字重排示例仍只演示单项任务。

## 连接格式

编辑时可暂缺，但写入正式连接前结构要齐。

当前工具以 modules/ 下的直接目录为成员，不另写清单，因此每个模块只有一个目录父级；画布打包会移动目录，不会创建成员引用。改结构要成套：增删成员、改接口名时，目录与 connections.json 须一起改，避免遗留悬空引用。这是当前格式和工具的限制，不是组合必须唯一归属的通用原则。当前不支持同一模块被多个组合引用，共享实现代码也不等于复用同一模块成员。

当前工具只通过本层 connections.json 连接直接成员及自身输入输出，不跨层接内部模块。组合不可包含自身。

connections 是数组，每条含 from、to、info，可选 when 描述条件。端点含 module（直接成员稳定标识或 $self）和 port（命名输入输出项）。$self 在来源侧表示组合输入，在目标侧表示组合输出。接口及其要求仍在 INPUT.md 和 OUTPUT.md 维护，不在画布另存定义；配置检查不假装能理解自然语言要求。

采用新契约后，连接可选 kind 标记，只取 support（辅助）或 return（退回）；缺省按普通连接显示，不宣称它是主流程，填写非法值须报错。旧连接的自定义 kind 须先按本页“模块信息”中的升级约定核实用途，不直接启用新检查。标记只帮助阅读，不改变交接条件、执行顺序或停止条件。由维护者根据实际流程明确填写，工具不按模块名称、业务词或线条方向猜测。只在 connections.json 保存这项标记，不再为节点新增同义分类。

每条连接白话讲就是三点：端口（port）说明接哪口，info 说明传什么，when 说明什么时候才传。from、to 须指明具体的模块和端口，info 写清交接的材料，条件写在 when。接收内容须符合输入要求，不在交接中暗中改变信息含义。不同材料或需要分别追踪的来源使用独立命名接口；同一输入允许多个来源时，在输入要求中说明合并还是择一及其规则。

## 定义输入输出接口

每个普通模块或组合模块可以定义任意多个输入、输出，两种方向分别计数，也可以为零。使用画布的“定义接口”，或在 INPUT.md、OUTPUT.md 各自添加一块 interfaces 代码块。数组中每项包含 name（接口名称）与 description（要求）；同一方向的名称不能重复，名称只用字母、数字、下划线、短横线，以字母或数字开头，要求不能为空。

```interfaces
[
  { "name": "text", "description": "需要处理的非空文字" },
  { "name": "options", "description": "可选处理设置" }
]
```

接口数量以数组项数为准，空数组表示该方向无接口。定义块是接口名称及要求的正式依据，正文只补充共用条件和用法，不重复维护清单。画布修改时保留原有正文；若正文仍包含旧接口说明，修改者须同步核对。

尚未添加定义块的旧模块仍可使用，画布临时从明确命名的正文及已有连接识别接口，不自动改写。首次保存接口后以定义块为准。配置检查会核对已定义接口是否存在、方向是否正确；删除或改名须同步处理父组合及内部的引用，否则拒绝保存。单纯未被连接的接口允许保留，数量不受现有连线限制。

有成员反馈回路时，顶层 stop 写明确停止条件，PROCESS.md 引用它。停止条件的实际执行由项目实现或当前智能体负责，静态检查只判断是否填写。不把包含关系当作反馈。

## 旧版与升级

根目录没有 module.json 时，工具沿原 TREE.md 和 README 规格检查；旧格式校验器保留在 scripts/legacy/。新版工具只提供兼容读取，不自动移动或升级项目。新旧两种根格式不混装，迁移时整套采用工具及相应文件，按实施指引做三方比较和备份。未知版本报错，不按当前版本猜读。

状态、调用协议、调度存储和业务格式不在此强行统一；项目按需要确定并记录。模板没有自动三方合并、后台调度或升级服务。
